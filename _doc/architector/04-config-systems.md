# 🏛 Система конфигураций

Ранее проект использовал один огромный файл настроек. Если в нем появлялась опечатка в названии домена, сайт падал целиком. Теперь система конфигураций разделена на изолированные блоки.

## 1. engine.config (Настройки движка)
**Путь:** `config/engine.config`

Содержит только те настройки, которые влияют на то, **как** работает ядро CMS.
*   `logic` — версия движка (например, `alpha.0.0`).
*   `ui_ajax_forms` — включен ли AJAX для форм по умолчанию.
*   `connect_type` — протокол подключения (`https://` или `http://`).
*   `trusted_proxies` — список IP доверенных прокси (если сайт стоит за Cloudflare или Nginx).

**Правило:** Если вы обновляете ядро CMS, вам нужно менять только этот файл.

## 2. site.config (Структура сайта)
**Путь:** `config/site.config`

Содержит данные о вашей сети сайтов.
*   `domains_real` — маппинг реальных доменов (какой внешний домен на какой внутренний указывает).
*   `alliases_real` — аллиасы (поддомены) для каждого реального домена.
*   `domains_available`, `alliases_available` — включен или выключен конкретный сайт/аллиас.
*   `fillers` — какие блоки включены для каждого аллиаса.

**Правило:** Если вы добавляете новый домен или аллиас, вы меняете только этот файл. Структура ядра остается нетронутой.

## 3. site.stubs.config (Библиотека заглушек)
**Путь:** `config/site.stubs.config`

Хранит HTML-код и заголовки для страниц-заглушек (например, когда сайт на реконструкции). Движок берет заглушку отсюда по её ID.

## 4. Безопасное изменение (Mutate)
Вручную редактировать JSON-файлы через блокнот рискованно (можно нарушить синтаксис). 
Для изменения конфигов из кода (например, из админки) используется метод `Config::mutate()`.

Он гарантирует:
1.  Блокировку файла от параллельной записи (файл `.lock`).
2.  Чтение текущих данных.
3.  Применение изменений.
4.  Атомарную запись (если запись прервется, файл не испортится).
5.  Создание резервной копии (`.bak`).
