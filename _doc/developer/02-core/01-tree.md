# 💻 Ядро: Движок маршрутизации (tree)

`engine/tree.php` — это единственный файловый роутер проекта. Он заменил собой старые движки `chain` и `router`. Его задача — брать URL, физически проходить по папкам и находить нужный PHP-класс.

## Алгоритм работы

1.  Роутер получает массив сегментов URL (например, `['ru-ru', 'blog', 'post-1']`).
2.  Начинает с корневой папки `algoritm/` и читает `algoritm.rules.json`.
3.  Берет первый сегмент (`ru-ru`) и проверяет его по правилам `available`.
4.  Если сегмент прошел проверку:
    *   Роутер переходит в соответствующую папку (например, `lang/`).
    *   Проверяет флаг `auth`. Если `auth: true`, а пользователь — гость, роутер отдает `errors/403.php` и **останавливает** скрипт.
    *   Берет следующий сегмент (`blog`) и повторяет цикл.
5.  Когда сегменты заканчиваются, роутер подключает найденный PHP-класс и вызывает метод `default()`.

## Формат файла `.rules.json`

Каждый узел маршрута (каждая папка) описывается файлом `<имя_класса>.rules.json`.

```json
{
    "available": ["index", "blog", "[a-z0-9-]+|slug"],
    "auth": false
}
```

### Ключ `available` (Список правил)

Здесь указывается, какие сегменты URL разрешены на этом уровне. Поддерживаются следующие варианты:

*   **Пустая строка `""`**: Если URL пустой (пользователь зашел просто на `/`), вызывается метод `default()` текущего класса.
*   **`"|target"`**: Если URL пустой, но вы хотите перенаправить пользователя в папку `target/` (например, `"|list"`).
*   **Строгое совпадение `"index"`**: Если сегмент в точности равен `index`, роутер ищет папку `index/`.
*   **Регулярное выражение `"[a-z0-9-]+|slug"`**: Самый мощный инструмент.
    *   `[a-z0-9-]+` — шаблон, которому должен соответствовать URL.
    *   `|` — разделитель.
    *   `slug` — имя параметра, в который попадет значение.
    *   Если URL равен `/blog/my-first-post`, роутер найдет совпадение, запишет `my-first-post` в `$this->args['slug']` и перейдет в папку `slug/`.

### Ключ `auth` (Авторизация)

*   `false` — страница доступна всем.
*   `true` — страница доступна только авторизованным пользователям. 
Проверка происходит на уровне роутера. Если гость стучится сюда — он получит ошибку 403 еще до того, как загрузится PHP-класс страницы.

## Обработка ошибок

*   Если сегмент URL не найден в списке `available` — роутер отдает `errors/404.php`.
*   Если файл `.rules.json` битый (невалидный JSON) — роутер отдает `errors/500.php`.
*   Если PHP-класс страницы вернул из метода `default()` значение `false` — роутер также отдает `errors/404.php`.

## Пример работы

Допустим, запрос: `GET /ru-ru/blog/post-1`.

1.  `algoritm.rules.json` содержит `["[a-z]{2}-[a-z]{2}|lang"]`.
    Роутер видит `ru-ru`, сопоставляет с регулярным выражением, переходит в папку `lang/`.
2.  `lang/algoritm_lang.rules.json` содержит `["blog"]`.
    Роутер видит `blog`, переходит в `lang/blog/`.
3.  `lang/blog/algoritm_lang_blog.rules.json` содержит `["[a-z0-9-]+|slug"]`.
    Роутер видит `post-1`, сопоставляет, записывает в `$this->args['slug'] = 'post-1'`, переходит в `lang/blog/slug/`.
4.  Сегменты кончились. Роутер загружает `algoritm_lang_blog_slug.php` и вызывает `default()`.

*Обрати внимание: файл `.php` называется так же, как и папка, в которой он лежит (плюс родительская цепочка).*
