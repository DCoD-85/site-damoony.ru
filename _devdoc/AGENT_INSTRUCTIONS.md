# 🤖 БРИФИНГ ДЛЯ ИИ-АГЕНТОВ (Строгие инструкции)

## 1. Анализ контекста
Перед началом работы **обязательно** прочитай всю папку `_devdoc/` (особенно `features/` и `developer/`). Не задавай вопросы, ответы на которые есть в документации. Не выдумывай классы и методы — проверяй их существование в коде.

## 2. Процесс работы (Строгий Workflow)
1. **Запрос:** Попроси у пользователя полные листинги (`cat -n`) файлов, которые нужно изменить, и связанных с ними файлов (для контекста).
2. **План:** Предложи пошаговый план реализации (архитектура, какие файлы будут затронуты, какие тесты добавить). Дождись одобрения.
3. **Код:** Пиши только измененный кусок или полный листинг файла. Никакой лирики, только код и краткие, четкие пояснения.
4. **Передача:** Пользователь сам физически меняет файлы на своем ПК. Ты не выполняешь команды записи, если он не попросит.
5. **Git:** После каждой логической единицы работы (фича, фикс, рефакторинг) давай пользователю команды для коммита (`git add`, `git commit -m "feat/fix: описание"`). Никогда не оставляй несохраненные изменения на конец дня.
6. **Боевой тест:** После изменений в ядре (Core, Router, DB, Security) давай команды для прогона тестов (PHPUnit, PHPStan) и проси пользователя сделать смоук-тест на локальном (боевом) сервере (проверить открытие админки, фронтенда, сохранение данных).

## 3. Железные правила разработки
1. **Безопасность:** Никаких `eval()`, `extract()`, прямых SQL-запросов. Только `DataGateway`, `Fs::writeAtomic`, `Csrf::check`.
2. **Архитектура:** Строгое соблюдение MVC. Контроллеры только в `www/admin/controllers/`. Логика — в `corescripts/_lib/`.
3. **Стиль:** PHP 8.4, строгая типизация (по возможности), `<?PHP` в начале файлов, отступы табами.
4. **Тесты:** Любое изменение ядра (Core, Router, DataGateway) требует написания/обновления теста в `_dev/phpunit/`.
5. **Документация:** При добавлении фичи или изменении архитектуры — обнови соответствующий файл в `_devdoc/`.

## 4. Учет «слепых зон» (Чего делать нельзя)
- Нельзя писать сложные ORM-запросы в контроллерах (только через Gateway).
- Нельзя хардкодить пути (только через `Paths::`).
- Нельзя использовать `file_put_contents` (только `Fs::writeAtomic`).
- Нельзя добавлять тяжелые JS/CSS библиотеки без необходимости.
