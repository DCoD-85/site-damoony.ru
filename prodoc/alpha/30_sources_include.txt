================================================================
30_SOURCES_INCLUDE — sources/include.php
Загрузчик ядра. Единая точка подключения всех модулей sources/.
================================================================

ПУТЬ:  sources/include.php
РОЛЬ:  switchboard. Подключает модули в фиксированном порядке.

ВЫЗЫВАЕТСЯ ИЗ: main::init()
  include_once __DIR__ . DS . '..' . DS . 'sources' . DS . 'include.php'

----------------------------------------------------------------
АЛГОРИТМ
----------------------------------------------------------------
1. Определяются два корня:
     $sources_dir_new = __DIR__                  (sources/)
     $sources_dir_old = dirname(__DIR__).DS.'sources_old'

2. Список модулей в порядке загрузки:
     render, user, blacklist, vardump, log, core, db,
     library, system, language, messages, visuo, gmod, mod

3. foreach $sources_module:
     path_new = sources/<name>.php
     path_old = sources_old/<name>.php

     Приоритет:
       если is_file(path_new) → include_once path_new
       иначе если is_file(path_old) → include_once path_old
       иначе → error_file(...)

4. unset() всех временных переменных.

----------------------------------------------------------------
МОДУЛИ (в порядке загрузки)
----------------------------------------------------------------
  render      — рендер (render.php)
  user        — базовый класс user
  blacklist   — чёрный список
  vardump     — отладочный дампер
  log         — логгер
  core        — ядро (core.php + core/*)
  db          — БД (db.php + db/*)
  library     — библиотека утилит (library.php + library/*)
  system      — системные функции
  language    — языки
  messages    — сообщения (info/error/...)
  visuo       — движок visuo (sources/visuo.php — обёртка)
  gmod        — игровые модули (football/test/user)
  mod         — моды

----------------------------------------------------------------
ЗАМЕЧАНИЯ
----------------------------------------------------------------
1. Порядок загрузки важен. Например, core грузится после render/user,
   но перед db/library — потому что db использует core constants.
   Не менять без понимания зависимостей.

2. Механизм fallback на sources_old — «переходный период».
   Если sources_old отсутствует как папка — модуль должен быть
   в sources/, иначе error_file. Сейчас sources_old фактически
   не используется — все модули в sources/.

3. include_once + `or error_file(...)`:
   `! include_once` сработает только при реальной ошибке включения.
   Если файл уже был подключён ранее — include_once вернёт true,
   и or-ветка не сработает. Это ок для идемпотентности, но
   маскирует отсутствие файла (проверяется через is_file до).

4. Нет проверки class_exists после include. То есть если файл
   есть, но класс в нём не объявлен — ошибка отложится до new.

5. unset() в конце — чистка области видимости include.php.
   Полезно: include_once не создаёт свою область, переменные
   летят в main::init(). Без unset могли бы затереть чужие.

----------------------------------------------------------------
ПОДСЛЕДСТВИЯ
----------------------------------------------------------------
  После main::init() доступны классы:
    render, user, blacklist, vardump, log, core, db,
    library, system, language, messages, visuo (?), gmod, mod

  main::init() затем new'ит их:
    core, user, blacklist, log, vardump, db, library,
    language, messages, gmod, mod

  visuo и render — создаются в main::init() как singleton-поля
    ($this->render, $this->visuorelease, ...).
