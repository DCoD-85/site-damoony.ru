B. dataprovider_base.php
================================================================
abstract class dataprovider_base

СВОЙСТВА
  main        : \main
  facade      : dataprovider     (обратная ссылка на visuo-фасад)
  localname   : string = 'visuo_damoony'    — имя БД

МЕТОДЫ
  __construct( dataprovider $facade )
  query($sql, $params) : \db_query_interface
      $main->db->open(localname)
      $main->db->query($sql, $params)
      → объект с методами row() / result() / affected() / insert_id()

КОНВЕНЦИЯ
  Плейсхолдеры в SQL: %s / %d — подставляются параметрами.
  Каждый метод-аксессор делает query(...)->row() / ->result().

E. dataprovider_news.php
================================================================
ТАБЛИЦА: news
WHITELIST WRITABLE (const) — только эти поля разрешены к записи:
  slug, title, excerpt, content_md, content_html, status,
  author_id, lang, published_at

READ
  recent($limit = 10, $lang = 'ru-ru')
  by_slug($slug, $lang = 'ru-ru')
  by_id($id)
  slug_exists($slug, $lang, $exclude_id = 0)

WRITE
  create(array) : int   (filter_writable)
  update($id, array)    (filter_writable)
  publish($id)          — status='published', published_at=NOW()
  archive($id)          — status='archived'
  delete($id)

ЗАМЕЧАНИЯ
- filter_writable() отсекает всё, чего нет в WHITELIST.
- Публикация не устанавливает автора автоматически.

================================================================
ЗАМЕЧАНИЯ ОБЩИЕ
================================================================
1. Все методы открывают БД через query() — без кэша открытия.
   db->open() должен быть идемпотентным.
2. query-параметры передаются массивом; SQL-шаблоны используют
   %s / %d. Экранирование — на стороне db.
3. Единая БД для всех: 'visuo_damoony'.
4. dataprovider_doc::search() требует FULLTEXT-индекса, иначе SQL-ошибка.
