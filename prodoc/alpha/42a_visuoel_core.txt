================================================================
B. visuoel.php — корневой класс API
================================================================
РОЛЬ
  База и корень дерева UI-элементов. Все конкретные элементы
  (form, input, field, table, block, message, tabs, button, group)
  наследуют visuoel.
  Корень — прозрачный (без обёртки); обёртку рисует группа/элемент.

СВОЙСТВА (refs и state)
  parent          : ?visuoel
  visuoel         : ?visuoel        — корень дерева (self на root)
  init            : bool = false    — флаг инициализации
  singleton       : bool = true     — режим фабрик (переиспользовать узлы)
  __data          : ?visuoel__data  — данные узла
  vt_start        : ?visuotag       — верх поддерева (attach point)
  vt_end          : ?visuotag       — слот: дети пришиваются сюда
  elements        : array           — [ visuoel | visuotag, ... ]

  Ссылки на фабрики (создаются лениво):
    visuoel_group, visuoel_form, visuoel_tabs, visuoel_input,
    visuoel_field, visuoel_button, visuoel_block, visuoel_message,
    visuoel_table

CONFIG (для override)
  protected string $tag       = 'div'
  protected string $css_class = 'visuoel'

================================================================
ЖИЗНЕННЫЙ ЦИКЛ
================================================================

__construct(?visuoel $parent = null, ?visuoel__data $__data = null)
  $parent, $visuoel = parent?->visuoel ?? $this
  $__data = $__data ?? $this->make_default_data()

make_default_data() : visuoel__data
  Хук для подклассов — свой тип __data.
  База возвращает new visuoel__data($this).

build() : void
  Хук для подклассов — собственный скелет.
  База:
    $vt = new visuotag();
    vt_start = vt_end = $vt;   ← прозрачный корень

init() : void
  Идемпотентно (init=true при первом вызове).
  1. build()
  2. foreach elements:
       visuoel  → el->init(); vt_end->append(el->vt_start)
       visuotag → el->prepare(); vt_end->append(el)
  Порядок инициализации: сначала дети, потом... нет, на самом деле
  дети в elements, а init сам родитель уже вызван.

ПРИНЦИП vt_start / vt_end
  vt_start — верхняя точка узла в дереве. Её родитель пришивает
             к своему vt_end.
  vt_end   — точка, куда пришиваются дети данного узла.
  Для простого элемента vt_start === vt_end (один узел).
  Для составного (input с label) vt_start — обёртка, vt_end —
  контейнер, куда кладётся сам <input>.

================================================================
ФАБРИКИ (lazy)
================================================================
Все фабрики однотипны:
  form()    → visuoel_form
  tabs()    → visuoel_tabs
  input()   → visuoel_input
  field()   → visuoel_field
  button()  → visuoel_button
  block()   → visuoel_block
  message() → visuoel_message
  table()   → visuoel_table

Логика каждой:
  if (singleton && <свойство> !== null) return <свойство>;
  $el = new visuoel_<type>($this, $__data);
  if (visuoel_group === null) visuoel_group = $el;
  <свойство> = $el;
  elements[] = $el;
  return $el;

  То есть каждая фабрика:
    - создаёт элемент,
    - если групповая ссылка ещё не установлена — фиксирует этот
      элемент как групповой (первый созданный становится визуоel_group).
    - возвращает созданный элемент.

СИНГЛТОН
  singleton=true (default) → повторные вызовы возвращают тот же
                             элемент.
  singleton=false          → каждый вызов создаёт новый.

  Переключение делается через `$el->singleton = false` перед фабрикой.
  Все фабрики также доступны через visuoel::data()? Нет — только
  через прямое свойство.

================================================================
ДОБАВЛЕНИЕ / УДАЛЕНИЕ ДЕТЕЙ
================================================================

add(visuoel|visuotag $el) : $this
  Если $el — visuoel и у него уже другой parent:
     old_parent->remove($el)
  $el->parent = $this
  elements[] = $el

remove(visuoel|visuotag $el) : bool
  Поиск по строгому ===. Найден:
    если visuoel → child->parent = null
    unset + array_values
    return true
  Иначе false.

remove_class(string $class) : int
  Удаляет всех детей, которые instanceof $class.
  Возвращает количество удалённых.

clear() : $this
  parent = null у всех visuoel-детей, elements = [].

================================================================
ГЕТТЕРЫ
================================================================
data()        : ?visuoel__data
css_class()   : string
tag()         : string
is_root()     : bool    — parent === null

get_input_text__data() / _hidden__data / _password__data / _submit__data
  Прокси на visuoel_input->get_<type>__data().
  Четыре shortcut'а — под частые случаи.

================================================================
RELEASE / SHOW
================================================================
release() : string
  if !init → init()
  if vt_start === null → ''
  return vt_start->release()

show() : string
  Алиас release().

================================================================
C. visuoel__data — базовый data-объект
================================================================
СВОЙСТВА
  node : visuoel

МЕТОДЫ-ПРОКСИ
  add($el)                  → node->add($el),       return $this
  remove($el)               → node->remove($el)
  remove_class($class)      → node->remove_class($class)
  clear()                   → node->clear(),        return $this

РОЛЬ
  Базовый класс «данных» visuoel. Подклассы добавляют свои поля
  (например, visuoel_input_text__data хранит value, placeholder...).
  Позволяет разделить:
    - конфиг/значения (__data),
    - сам узел/логику (visuoel).
  Фабрики принимают $__data как аргумент — можно передать готовый
  конфиг.

================================================================
ОБЩИЙ ПАТТЕРН
================================================================

A. Создание дерева
   $el = new visuoel();           // корень, прозрачный
   $el->block()->data()->set(...);
   $el->message()->info()->data()->set('OK');
   // при release: init → build → дети → release

B. Form + fields
   $form = $el->form()->form();   // visuoel_form::form()
   $form->field()->text()->data()->set('login');
   $form->field()->password()->data()->set('pass');
   $form->field()->submit()->data()->text('Sign in');

C. Singleton
   $el->block()->html()->data()->set('x');
   $el->block()->text()->data()->set('y');
   // Второй вызов block() вернёт тот же объект (singleton).
   // Чтобы создать второй блок:
   $el->singleton = false;        // (или локально)

D. Вставка в HTML-дерево
   $center = $main->alliasglobal->center;
   $center->visuotag()->el($el);
   // visuotag::el() создаёт <el class="cl_el"> + привязывает visuoel.
   // На prepare() содержимое vt_start вставляется в дерево.

================================================================
ЗАМЕЧАНИЯ / БАГИ
================================================================
1. singleton — глобальный флаг на узле. Переключается ВРУЧНУЮ;
   при переключении в false фабрика создаёт новый элемент, но
   ссылка на старый сохраняется в свойстве (visuoel_form и т.д.),
   так что следующий вызов с singleton=true вернёт ПОСЛЕДНИЙ,
   а не первый. Неожиданно.

2. visuoel_group — «первый созданный элемент становится групповым».
   Не совсем ясна семантика. Возможно, для случаев, когда есть
   один основной контейнер в узле.

3. remove_class($class) использует instanceof — работает только
   для class-имён. Если передать несуществующий класс — 0 удалённых,
   без ошибки.

4. init() вызывает $el->prepare() для visuotag-детей (см. 38_visuotag).
   Это обязательная фаза для узлов-хуков (visuoelement / visuoel
   внутри visuotag). Порядок важен.

5. vt_start у простого элемента = vt_end = один узел. Для
   составных (input+label) — разные. Это внутренний контракт
   подклассов.

6. Геттеры get_input_*__data() — прокси в visuoel_input. Работают
   только если visuoel_input уже создан. Иначе null.

7. Нет метода, который бы вернул «все дочерние visuoel» или
   «все visuotag» отдельно. Только elements как единый массив.

8. __data в конструкторе — можно передать готовый объект. Но
   make_default_data() вызывается через `??` — то есть только
   если $__data === null. Если передали, свой data не создаётся.
   Это позволяет подклассам работать с предустановленным конфигом.
