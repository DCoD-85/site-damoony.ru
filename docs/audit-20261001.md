# Аудит проекта damoony.ru

**Дата:** 2026-10-01
**Автор:** агент
**Область:** ядро `sources/*`, аллиас `visuo`, `alliasglobal`, `alliasscheme`, БД `visuo_damoony`
**Выведены из области аудита (переработка с нуля):** аллиас `www`, аллиас `login`, БД `login_damoony`, БД `test`

## Краткое резюме

Проект — движок для мультиязычных сайтов на PHP 8.4 + MariaDB 11.8 с аллиасной архитектурой. Ядро — это switchboard `sources/include.php` с фиксированным порядком загрузки 15 модулей-агрегаторов. Аллиас `visuo` — независимый модуль поверх ядра. Собственный UI-движок `visuoel`/`visuotag`. Собственный роутер `algoritm_` с regex-паттернами.

**Общая оценка: 7.5 / 10.**

**Что хорошо:**

- Ядро архитектурно последовательно. Namespace-конвенции выдержаны (`core_*`, `config_*`, `db_*`, `visuo*`, `gmod_*`, `library_*`).
- Драйвер БД `db/mysqli/query.php` — зрелый: prepared statements, парсер `%s`/`%d`, валидация типов, ленивое выполнение, авто-`LIMIT`.
- Аллиас `visuo` — эталонная реализация аутентификации: `password_hash`/`password_verify`, сессии в БД с TTL, brute-force защита, роли, `can()`.
- `dataprovider_*` (visuo) — prepared statements, whitelist полей, FK в схеме.
- `alliasblock` / `alliasglobal_menu` — чистые и хорошо спроектированные.
- 14 FK в `visuo_damoony` — целостность на уровне БД.

**Что критично:**

- `error_reporting(~E_ALL & ~E_NOTICE)` в `www/index.php` — скрывает все ошибки, включая фатальные.
- CORS в `visuo\algoritm::logic()` строится из `$_SERVER['HTTP_REFERER']` — фактически открытый CORS.
- `content_html` рендерится без санитайза в `docs_page`/`news_page` — потенциальный stored XSS.
- N+1 запросы в `docs` — два места: `right_visuo::menu_docs` и `docs::render_list`.
- Баг в `algoritm_::include_ext`: `$this->algoritm_classes[$url_base_pos - 1]->release()` при отсутствии класса.

**Что нормально:**

- Ядро загружается без циклов.
- Роутинг работает.
- Схема БД `visuo_damoony` — почти образцовая.

## 1. Ядро (sources/*)

### 1.1 Схема загрузки

Единая точка входа — `sources/include.php` (switchboard). Порядок фиксирован:

```text
render → user → blacklist → vardump → log → core → config → db →
library → system → language → messages → visuo → gmod → mod
```

Каждый модуль грузится как `include_once sources/<name>.php`. Фолбэк в `sources_old/<name>.php` — папки нет, ветка мёртвая.

Подмодули грузятся лениво из конструкторов агрегаторов: `core/*`, `config/*`, `db/*`, `library/*`, `visuo/sources/*`.

### 1.3 Ключевые модули

**`db/mysqli/query.php`** — зрелый. `parse_sql(%s/%d → ?)`, `detect_type()`, `validate_types()`, `coerce_value()`, `apply_limit()` (one → LIMIT 1, limit(n), page(n,s) с `$_GET['p']`/`p_max`, дефолт `DB_LIMIT_MAX=1000`). Legacy-обёртки `select/insert/insert_legacy` оставлены для совместимости.

**`db/schema.php`** — DDL-билдер. `create/drop/truncate/rename`, интроспекция `tables/exists/columns_of`, helper `col()`.

**`db.php`** — агрегатор. Замечание: `db::insert/update/delete` строят SQL с именами таблиц/колонок через конкатенацию. Значения — через `%s`. Риск SQL-инъекции только если имена таблиц/колонок приходят из ввода (на практике — литералы).

**`library/link.php::ahref()`** — сборка URL без urlencode для query-части. Значения с `&`, `=`, пробелами сломают URL. TODO(audit): проверить вызовы с пользовательскими значениями.

**`sources/user.php`** — legacy-модель: пароль в plain-text cookie + сравнение в SQL без `password_hash`, `md5($login.$password.time())`. Для `visuo` эта модель не используется (там `damoony\visuo\user extends \user`), но `main::init()` вызывает `user->authorized()` из старого кода. После удаления `login_damoony` — отключить вызов и ревизовать.

## 4. Роутинг

### 4.1 Цепочка

```text
www/index.php → main::main() → path → init → logic → savedata → release
```

- `path()` — парсит URL регуляркой.
- `init()` — загружает ядро + `www/logic/alpha.0.0/include.php`. Важно: в конце `init()` открывается `login_damoony` (уходит после её удаления).
- `logic()` — создаёт `domain`, `domainglobal`, `dataprovider`, `allias`, `alliaslocal`, `alliasglobal`, `alliasscheme`, `algoritm`.
- `algoritm->start()` → `scheme->load('visuo')` → `algoritm->release()` → `release_()` → `include_ext()` → вложенный роутинг.
- `algoritm->logic()` — ставит CORS-заголовки.
- `scheme->reload()`.

### 4.2 Роутер algoritm_

Ключевая особенность: `available` может содержать regex-паттерны через `|`:

```php
'available' = [ 'index', '([a-z]{2}-[a-z]{2})|lang', 'tests' ]
```

Обработка: строка с `|` разбивается на `[pattern, replacement]`. `mb_ereg` матчит URL-сегмент, при совпадении `$url_base[$pos] = $replacement`. Умно, но `$args`, собранные из `$matches`, в `include_ext` не используются.

### 4.4 Баг include_ext

```php
} else {
    http_response_code( 403 );
    $this->algoritm_classes[ $url_base_pos - 1 ]->release( );
}
```

Если `class_exists($class) === false` — падает в этот else. При `$url_base_pos = 0` — `$this->algoritm_classes[-1]` → warning + fatal. Смысл неясен, недоделка.

### 4.5 307-редирект handle_language

Любой URL без языкового префикса редиректится с 307. Работает корректно, но лишний round-trip. Для SEO обычно 301, но это уже к оптимизации.

## 5. Циклические зависимости

**Циклов нет.**

Полная цепочка `include_once` — линейная. `visuo/visuo.php` грузит `visuotag.php` и `visuoattrs*.php` до `visuoel` и `visuoelement` — порядок соблюдён. `visuoels.php` дублирует `include_once` на некоторые файлы, но через `_once` — безопасно.

`algoritm_::include_ext` рекурсивно подключает вложенные алгоритмы. Цикл возможен только если `available` содержит бесконечный паттерн — на практике нет.

## 8. Безопасность

### 8.1 Критические

**CORS из Referer** — `damoony\visuo\algoritm::logic()`:

```php
$referer = $_SERVER['HTTP_REFERER'] ?? '';
$access_origin = substr($referer, 0, strlen($referer) - 1);
header('Access-Control-Allow-Origin: ' . $access_origin);
header('Access-Control-Allow-Credentials: true');
```

Заголовок `Referer` контролируется клиентом. `Allow-Credentials: true` + динамический origin = открытый CORS. Плюс `substr(..., 0, -1)` отрезает последний символ.

**`content_html` без санитайза** — `algoritm_lang_docs_page` и `algoritm_lang_news_page` выводят `(string) $a['content_html']` без экранирования. Если контент приходит из WYSIWYG без серверного санитайза — stored XSS. Требуется проверить санитизацию при `article_create/update`.

**`error_reporting(~E_ALL & ~E_NOTICE)`** в `www/index.php` — побитовое НЕ. Фактически отключает показ всех ошибок, включая фатальные.

### 8.2 Высокие

- `algoritm_::include_ext` — баг с `$url_base_pos - 1` (см. 4.4).
- `sources/user.php` — plain-text пароль в cookie + сравнение в SQL без `password_hash` + `md5()`. После удаления `login_damoony` вызов отключается, но код остаётся в `sources/user.php`. Требует ревизии.
- `setcookie` в `handle_language`/`handle_skin` без `SameSite`/`HttpOnly`.

### 8.3 Средние

- `main::init()` устанавливает `connect_type = 'http://'` жёстко.
- `$_COOKIE['render'/'language'/'skin']` без `??` в `main_settings::__construct`.
- `$_GET['phpinfo']` без `isset()` в `www/index.php::error()`.
- `defined(TRUE)` вместо `defined('CONST')` — защита не работает.
- `main::logic()` создаёт классы из URL без `class_exists()` — неконтролируемый 404.
- `mime_type` в `dataprovider_files::create` не валидируется по whitelist.

### 8.4 Низкие

- `library_link::ahref()` — нет urlencode для query.
- `gmod::show_list()` — `$return .= ` без инициализации.

### 8.5 Что хорошо

- CSRF работает в `login`/`registration`/`profile`.
- `password_hash`/`password_verify` в `visuo\user`.
- Prepared statements везде в `dataprovider_*`.
- Path traversal защищён в `download_page`.
- `setcookie` в `visuo\user::set_cookie` — `HttpOnly`, `SameSite=Lax`, `Secure` по HTTPS.
- Brute-force защита в `check_bruteforce()`.
- FK в `visuo_damoony` покрывают связи.
