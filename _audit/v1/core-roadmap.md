## Дата и время: синхронизация сервер / клиент

**Проблема.** Сейчас используется серверное время (PHP `date()`, `time()`),
которое может отличаться от часового пояса пользователя.
Пример: пользователь в Москве видит сообщение "5 минут назад" для события,
которое произошло "1 час назад" по UTC.

**Что нужно.**
1. Сервер всегда хранит время в UTC (единая точка отсчёта).
2. Клиенту передаётся серверная метка + его таймзона (через JS).
3. При выводе время приводится к таймзоне клиента.

**Как реализовать.**

Слой ядра — `core\time`:
- `now()`              — текущее UTC время (замена `time()`)
- `format($ts, $tz)`   — форматирование по таймзоне
- `diff($ts)`          — "5 минут назад" с учётом tz
- `sync_client($tz)`   — запомнить tz клиента из POST/GET/cookie
- `client_tz()`        — текущая tz клиента (fallback: серверная)

Слой представления — `visuo` или атрибут:
- на `<body>` повесить `data-server-time` и `data-server-tz`
- JS при загрузке определяет клиентскую tz
- AJAX-запрос сообщает её серверу

Слой БД:
- все timestamp-поля хранятся в UTC
- при выборке — конвертация в нужную tz перед отдачей (или отдать UTC + tz клиента)
- `mysqli`: `SET time_zone = '+00:00'` при соединении

**Что учесть:**
- PHP по умолчанию использует `date.timezone` из php.ini — надо явно `date_default_timezone_set('UTC')` в `core\time`
- MySQL `CURRENT_TIMESTAMP` — тоже UTC, если соединение настроено
- Cookie "timezone" сохраняется при первом определении
- Форматы дат в интерфейсе — через locale (не `date('d.m.Y')` в шаблоне)

**Когда делать:** отдельный спринт. Не сейчас.

**Приоритет:** средний. Станет критичным, когда появятся "ленты", "уведомления", "история".
